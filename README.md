# ttcomm — TikTok-бот с управлением из Telegram

Переработанная версия [ainastrahnet/ttcomm](https://github.com/ainastrahnet/ttcomm): та же автоматизация TikTok
(поиск → анализ видео → комментарий), но **всё управление вынесено в Telegram-бота**.
Веб-панель, Express и `public/index.html` удалены — единственный интерфейс это чат с ботом.

```
Telegram  ──►  Bot API (long polling)  ──►  Bot engine  ──►  Chrome (CDP/Puppeteer)  ──►  TikTok
                                              │
                                              ├──► OpenAI (анализ + текст комментария)
                                              └──► SQLite (видео, комментарии, сессии, настройки)
```

## Что изменилось по сравнению с оригиналом

| Было | Стало |
| --- | --- |
| Express-сервер + веб-панель на `localhost:3000` | Только Telegram: команды, inline-кнопки, живые уведомления |
| Запуск/стоп только через веб | `/search`, `/feed`, `/stop`, `/pause`, `/resume` |
| Настройки только в `.env` (до перезапуска) | `/settings`, `/set`, `/reset` — меняются на лету и хранятся в SQLite |
| Комментарий публикуется сразу | Режим подтверждения: кнопки «Отправить» / «Пропустить» (включён по умолчанию) |
| Капча: тихо ждёт в консоли | Уведомление в Telegram + кнопка «Продолжить» |
| Ошибки только в консоли | Ошибки, пост-фактум и итоги сессии приходят в чат |
| sqlite3 (нативная сборка) + express + openai + dotenv | Только `puppeteer-core`; БД через встроенный `node:sqlite`, OpenAI через `fetch`, `.env` через `process.loadEnvFile()` |
| Генератор видео пересоздавался на каждой итерации (баг) | Один генератор на сессию, корректный `StopError` и отмена ожиданий |
| Фолбэк-комментарий «Great video! 👍» при ошибке AI | При ошибке AI комментарий не публикуется вообще |
| Нет защиты от дублей | Проверка `hasCommentText` + фильтр запрещённых слов/ссылок/упоминаний |
| Доступ у всех, кто открыл панель | Allowlist по `TELEGRAM_ADMIN_IDS` |
| Не было тестов | 42 unit-теста на `node:test` (форматирование, команды, настройки, движок бота, notifier, роутинг команд) |
| Dockerfile указывал на несуществующий `src/api/server.js` | Рабочий `node:24-slim` + compose с отдельным Chrome |

## Быстрый старт

Нужен **Node.js 22.16+** (используется встроенный модуль `node:sqlite`).

```bash
git clone https://github.com/getene761-cell/ttcomm-telegram.git
cd ttcomm-telegram
npm install
cp .env.example .env
# отредактируй .env: TELEGRAM_BOT_TOKEN, TELEGRAM_ADMIN_IDS, OPENAI_API_KEY
```

### 1. Telegram-бот

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → получи токен.
2. Свой user id узнай у [@userinfobot](https://t.me/userinfobot) и впиши в `TELEGRAM_ADMIN_IDS`.

### 2. Chrome с отладкой и логином в TikTok

```bash
google-chrome-stable \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-ttcomm \
  --disable-blink-features=AutomationControlled \
  --window-size=1366,768
```

Открой TikTok в этом окне и войди в аккаунт. Бот подключается к уже запущенному Chrome,
пароли и cookies он не хранит.

### 3. Запуск

```bash
npm start
```

В Telegram: `/start` → `/search удалённая работа`.

## Команды

| Команда | Что делает |
| --- | --- |
| `/start`, `/help` | Меню и справка |
| `/status` | Состояние: режим, время, счётчики, капча, ожидающий комментарий |
| `/search <запрос>` | Запустить поиск по запросу |
| `/feed` | Листать ленту «Для тебя» |
| `/stop` | Остановить (итоги придут в чат) |
| `/pause`, `/resume` | Пауза и продолжение |
| `/stats` | Статистика за всё время |
| `/videos [n]`, `/comments [n]` | Последние обработанные видео и комментарии |
| `/settings` | Текущие настройки |
| `/set <ключ> <значение>` | Изменить настройку на лету |
| `/reset <ключ\|all>` | Вернуть значение из `.env` |
| `/captcha` | Отметить капчу как решённую вручную |
| `/id` | Показать свой Telegram id |

Всё, что не команда, бот игнорирует с подсказкой — случайное сообщение не запустит сессию.

## Настройки (`/set`)

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `min_relevance_score` | `0.7` | Порог релевантности (0..1) |
| `comment_delay_seconds` | `30` | Пауза после успешного комментария |
| `max_comments_per_hour` | `20` | Лимит комментариев в час |
| `video_delay_min` / `video_delay_max` | `3` / `8` | Пауза перед следующим видео, сек |
| `session_max_minutes` | `120` | Автостоп сессии |
| `approval_mode` | `true` | Подтверждать каждый комментарий кнопкой |
| `approval_timeout_seconds` | `300` | Сколько ждать подтверждения |
| `comment_language` | `ru` | `ru`, `en`, `es`, `de`, `fr`, `pt`, `it` |

Пример:

```
/set min_relevance_score 0.8
/set approval_mode off
/set comment_language en
```

Значения хранятся в SQLite и перекрывают `.env`; `/reset all` возвращает значения из окружения.

## Как проходит сессия

1. Подключение к Chrome и проверка авторизации в TikTok.
2. Поиск по запросу (или лента) → список видео, уже обработанные пропускаются.
3. Просмотр с человеческими задержками, сбор лайков/комментариев.
4. LLM оценивает релевантность (0..1) и контекст обсуждения.
5. Если релевантно и выше порога — генерация короткого комментария
   (без ссылок, слов «бот», «сервис», «AI» и т.п.).
6. Проверка на дубли → запрос подтверждения в Telegram → публикация.
7. Соблюдаются лимиты: минута/час, пауза после комментария, максимальная длина сессии.

События, которые сразу прилетают в Telegram: старт сессии, комментарий на подтверждении,
успешная публикация, капча, ошибка, итоги сессии. Текущий статус редактируется в одном
сообщении не чаще `STATUS_UPDATE_SECONDS`, чтобы не спамить.

## Docker

```bash
cp .env.example .env   # заполнить токены
docker compose up -d --build
```

Compose поднимает два контейнера: `chrome` (CDP на 9222) и `bot`.
При первом запуске залогинься в TikTok в контейнерном Chrome — проще всего через
`/json/version` + отдельный браузер, либо пробросить готовый профиль в том `chrome-data`.

## Структура

```
src/
├── index.js              точка входа: env, БД, polling, graceful shutdown
├── config.js             валидация .env (падает с понятным списком ошибок)
├── settings.js           настройки, редактируемые из Telegram
├── logger.js             уровни логирования
├── db.js                 node:sqlite: видео, комментарии, сессии, настройки
├── ai.js                 OpenAI через fetch: анализ + генерация + фильтры
├── stealth.js            задержки, мышь, ввод, скролл
├── browser.js            CDP: поиск, лента, комментарии, публикация, капча
├── bot.js                ядро (EventEmitter): сессия, лимиты, подтверждения
├── notifier.js           события бота → сообщения в Telegram
└── telegram/
    ├── api.js            Bot API: long polling, send/edit, callbacks
    ├── commands.js       парсинг команд и справка
    ├── format.js         HTML-сообщения (экранирование, статус, статистика)
    └── app.js            роутинг команд и callback-кнопок, авторизация
test/
├── app.test.js           авторизация, команды, callback-кнопки
├── bot.test.js           движок: сессия, подтверждения, дубли, стоп
├── commands.test.js
├── format.test.js
├── notifier.test.js      статус, кнопки подтверждения, капча
└── settings.test.js
```

## Тесты

```bash
npm test        # node --test
```

Покрыты чистые части и логика без сети: экранирование HTML, форматирование статусов,
парсинг команд, валидация/слияние настроек, движок бота на фейковом браузере и AI,
отправка уведомлений на фейковом Telegram-клиенте. Сетевые вызовы (Telegram, OpenAI, Chrome)
в тестах не участвуют.

## Известные ограничения

- Селекторы TikTok меняются: при изменениях вёрстки правь `SELECTORS` в `src/browser.js`.
- Публикация комментария подтверждается косвенно (капча/ошибки ввода); защита от теневого бана не гарантируется.
- Нужен заранее залогиненный Chrome — бот не умеет проходить вход.
- Один бот обслуживает всех админов из списка: управление общее.

## ⚠️ Важно

`approval_mode`, соблюдай лимиты и не рассылай рекламу. Ответственность за использование — на тебе.
